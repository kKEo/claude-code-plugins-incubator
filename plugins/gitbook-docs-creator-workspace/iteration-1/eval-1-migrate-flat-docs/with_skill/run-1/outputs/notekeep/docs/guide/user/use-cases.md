# Use cases

This page gives three examples of what notekeep is good for. They are illustrations built
from what notekeep can do, not reports from real teams.

## A shared list that everyone can update

**Who.** A small team that shares an office.

**The problem.** The shopping list lives on a whiteboard, and nobody sees it from home.

**How notekeep helps.** One person runs notekeep. Everyone saves to the same title, and the
note always shows the latest text.

**What they do.** They save the list as described in
[Change a note](everyday-use.md#change-a-note).

## Notes on your own computer

**Who.** One person who wants short notes without an account anywhere.

**The problem.** Online note services keep the notes on someone else's computer.

**How notekeep helps.** notekeep runs on your computer and keeps the notes in one file
there. Nothing is sent anywhere else.

**What they do.** They follow the [Quick start](quick-start.md), then save and
[read notes](everyday-use.md#read-a-note) on the same computer.

## Notes that scripts write

**Who.** Someone who has a script that runs every night.

**The problem.** The result of the script should be easy for the team to find.

**How notekeep helps.** Saving a note is one command, so a script can do it. The list shows
when each note was last saved.

**What they do.** The script sends its result as in
[Save a longer note from a file](everyday-use.md#save-a-longer-note-from-a-file), with the
team's [token](everyday-use.md#use-a-token).

## When notekeep does not fit

notekeep is not the right tool when you need to read notes from another computer, keep
earlier versions of a note, or give different people different rights.
