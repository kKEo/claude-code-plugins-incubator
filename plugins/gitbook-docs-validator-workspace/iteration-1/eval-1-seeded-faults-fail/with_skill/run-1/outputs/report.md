## Template deviations (judge)

- `operator/README.md` and `user/README.md` — cross-book callout links only one sibling. The user README sends readers to the operator guide only; the operator README sends readers to the user guide only. Neither mentions the tester guide (`../tester/`). The tester README does link both siblings. Together with the missing landing card this means a reader can only discover the tester book by URL. Reasonable to fix; not a build breaker.
- `operator/README.md:1` — H1 "memors-mcp operator guide" vs SUMMARY title "Introduction". Cosmetic; mdBook shows the H1, the sidebar shows "Introduction". Acceptable, but aligning them avoids two names for one page.
- `operator/README.md:31`, `operator/config/profiles-json.md:7,62`, `operator/monitoring/catalogue.md:3` — prose quotes "v1.4" as the current release. This drifts on every release. Prefer "the shipped defaults" plus the `memors-mcp profiles show` / `--help` pointer already given.
- `tester/README.md:38`, `tester/gates/docs.md:28-30`, `tester/contributing/README.md:42-43`, `tester/explore/README.md:5`, `tester/scenarios/README.md:50,59-60` — nine absolute links to `https://github.com/example/project/...` (placeholder org) for the generated scenario log, gaps and catalogue pages. The repository elsewhere is `github.com/kKEo/memors` (`book.toml`, `index.html` footer). These are dead links in the published tester book. Also, the pages they point at (`scenarios/log/`, `scenarios/gaps.md`, `scenarios/catalogue.md`) are not in this tree; if they are generated by `make scenario-docs` they are missing from the fixture, and if they live only in the repo they should be linked with the real repository URL.
- Product naming — the repo is `acme-notes` but every page, `book.toml` title and the landing page describe `memors-mcp`. If these docs were copied as a starting point for acme-notes, the content has not been adapted yet; if the product really is memors-mcp, the repo name is the odd one out. Decide before publishing.
- No repository integration (`--repo-root` found no root `README.md`, no `docs/README.md`, no `Makefile`, no `.github/workflows`, no `scripts/docs-check`). The task says the repo only contains docs, so this is expected here, but the published site will have no build (mdBook workflow copying `index.html` to the site root) until those exist.
