# Review of `docs/guide` (acme-notes) against the standard layout

**Verdict: not ready to publish.** The tree has the right shape (one landing page plus `user/`,
`operator/` and `tester/` books), but there are structural faults that would break a build or
hide pages, plus a number of smaller defects. Nothing was modified.

Checked: every `.md` under `docs/guide` (116 files), `index.html`, each book's `SUMMARY.md`,
`README.md`, `book.toml` and `.gitbook.yaml`; every relative link, image reference and
`#anchor`; SUMMARY coverage (orphans and missing targets); placeholder text; stub pages;
heading structure; unused images.

## 1. Blocking faults

| # | Where | Problem |
|---|---|---|
| 1 | `docs/guide/index.html` | The landing page links only the **user** and **operator** guides. There is no card for the **tester guide**, so the third book is unreachable from the landing page even though the page's own `<meta name="description">` promises "User guide, operator guide and tester guide". There is also a stray blank/indented `</div>` where the third card should be, which suggests the card was deleted. |
| 2 | `docs/guide/tester/` | **Missing `.gitbook.yaml`.** The user and operator books both have one (`root: ./`, `structure.readme`/`summary`); the tester book has only `book.toml`. GitBook will not pick up the tester book's `README.md`/`SUMMARY.md` consistently with the other two. |
| 3 | `docs/guide/operator/SUMMARY.md` | Lists **`install/windows.md` ("Windows service")** under Part II, but the file does not exist. With `create-missing = false` in `book.toml`, mdBook fails the build; GitBook shows an empty chapter. Either add the page or drop the entry. |
| 4 | `docs/guide/user/orphan-page.md` | **Orphan page.** "Sharing a memory with a colleague" is not in `user/SUMMARY.md`, so it is never published. It is also a stub (one sentence: "This page was written but never added to SUMMARY.md"). Add it to the summary and write it, or delete it. |
| 5 | `docs/guide/operator/README.md` | **Broken relative link**: `[Architecture](../../architecture.md)` resolves to `docs/architecture.md`, which does not exist in this repo. It also leaves `docs/guide/`, which the project's own docs gate (`tester/gates/docs.md`, rule 1) forbids: links to other repository files must be absolute GitHub URLs. Every other reference to the architecture doc already uses `https://github.com/kKEo/memors/blob/master/docs/architecture.md`; this one should too. |

## 3. Minor / consistency notes

- `operator/SUMMARY.md` titles the book's README "Introduction" while the page's H1 is
  "memors-mcp operator guide". The user and tester books match their H1s ("Welcome", "For
  testers"). Cosmetic, but inconsistent.
- `user/README.md` and `operator/README.md` each cross-link to the other book but neither
  mentions the tester guide; `tester/README.md` links to both of them. Combined with #1, the
  tester guide is only discoverable from three deep operator pages
  (`install/source.md`, `operations/release.md`, `tuning/measuring.md`).
- `tester/explore/README.md:6` reads "...or a scenario waiting to be written." This is prose, not
  a placeholder; noted only because it tripped the placeholder scan.

## 4. What passed

- All three `book.toml` files are consistent (title, `src = "."`, `build-dir`, `site-url`,
  edit URL template, search enabled).
- Every relative link and image reference resolves, except #5 and #3 above.
- Every `#anchor` fragment matches a heading in its target page.
- All 13 SVG images under `*/images/` are referenced by at least one page; none are unused.
- No `TODO`/`TBD`/`FIXME`/"lorem ipsum" placeholders in page bodies (the one `lorem ipsum`
  hit in `tester/explore/sandbox.md:36` is legitimate prose).
- No duplicate SUMMARY entries; apart from #4 every page in each book is listed in its
  `SUMMARY.md`.
- `user/` and `operator/` have `.gitbook.yaml`, `README.md` and `SUMMARY.md` that agree with
  each other.

## 5. Suggested fix order

1. Add the tester card to `index.html` (#1).
2. Add `tester/.gitbook.yaml` mirroring the other two books (#2).
3. Remove or write `operator/install/windows.md` (#3).
4. Add `user/orphan-page.md` to `user/SUMMARY.md` and write it, or delete it (#4).
5. Fix the `../../architecture.md` link in `operator/README.md` (#5).
6. Replace `github.com/example/project` with the real repository, and either commit the
   generated scenario pages or remove the references (#6, #7).
7. Demote `# Running on Windows` to `##` (#8).
