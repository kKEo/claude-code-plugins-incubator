# What is in the marketplace

This page lists every plugin in a sentence or two, so you can decide which to install. Each has a page of its own with what to type, how it works and what it reads and writes.

## frontend-scaffold

Builds a complete Vue 3 web application from a one-line description, and can check a generated project later.

[More about frontend-scaffold](frontend-scaffold.md)

## feature-dev-documentalist

Writes a short document for each phase of a feature you are building, by looking at what changed in git, and reminds you when a feature branch has none yet.

[More about feature-dev-documentalist](feature-dev-documentalist.md)

## gitbook-docs-validator

Checks a documentation folder against a fixed three-book layout and reports what is missing or deviates.

[More about gitbook-docs-validator](gitbook-docs-validator.md)

## implementation-spec

Writes a specification for a feature that does not exist yet, complete enough for an agent to build it without asking you more.

[More about implementation-spec](implementation-spec.md)

## rigorous-review

A strict review of a change before it is merged: bugs, security holes, performance traps and over-engineering, with a minimal fix for each finding.

[More about rigorous-review](rigorous-review.md)

## plan-progress

Shows the current plan and how far Claude has got with it in a pane beside the chat. A mod.

[More about plan-progress](plan-progress.md)

## session-cost

Lists every model request with its tokens and cost in a pane beside the chat, with totals by model and by day. A mod.

[More about session-cost](session-cost.md)

## prompt-coach

Collects the prompts you type, shows a language correction for each in a pane beside the chat, and has a practice game built from your own mistakes. A mod.

[More about prompt-coach](prompt-coach.md)

## memors-hooks

Connects Claude to a local memors-mcp knowledge base, and reminds it to search before re-fetching and to record what it learns.

[More about memors-hooks](memors-hooks.md)

## Not a plugin

The repository also contains a folder named `gitbook-docs-validator-workspace`. It holds test runs and sample documentation used while developing the validator. It cannot be installed and you can ignore it.
